Snap! Functionality Overview
============================

Purpose
-------
This file maps the interaction and layout behavior of the original Snap!/Morphic
editor to the vendored source used by this project. It is intended to guide the
incremental replacement of high-level Morphic infrastructure with Scala.js and,
ultimately, SVG rendering.

All line numbers below refer to the repository's currently vendored sources:

  resources/programs/20260212TurtleStitch/turtlestitchsrc/blocks.js
  resources/programs/20260212TurtleStitch/turtlestitchsrc/morphic.js
  resources/programs/20260212TurtleStitch/turtlestitchsrc/widgets.js

Line numbers can move if that vendor snapshot is replaced. Search for the named
prototype method rather than relying on a line number alone.

The original outline excerpts and source references in

todomove/webElementsOld/webElements/svg/shapes/SnapShapeFactory.scala

must remain there. This overview supplements those local references; it does not
replace them.


1. Browser event orchestration
------------------------------
The original editor uses WorldMorph and HandMorph as its high-level browser event
and pointer-dispatch system.

World and event registration:

* WorldMorph constructor — morphic.js:12012
* WorldMorph.prototype.initEventListeners — morphic.js:12338
  Registers mouse, touch, wheel, drag/drop, resize, and context-menu related
  browser listeners. Mouse and touch events are forwarded to the world's hand.
* WorldMorph.prototype.doOneCycle — morphic.js:12141
  Runs scheduled stepping/animation work and redraws damaged canvas regions.

Pointer targeting and dispatch:

* HandMorph constructor — morphic.js:11187
* HandMorph.prototype.morphAtPointer — morphic.js:11283
  Finds the front-most visible morph under the pointer.
* HandMorph.prototype.allMorphsAtPointer — morphic.js:11287
  Produces the complete hit stack when dispatch or drop-target lookup needs it.
* HandMorph.prototype.dropTargetFor — morphic.js:11306
  Walks possible owners under the pointer and asks wantsDropOf whether a carried
  morph is accepted.
* HandMorph.prototype.processMouseDown — morphic.js:11393
  Identifies the clicked morph, remembers press state, and dispatches the proper
  mouseDown event.
* HandMorph.prototype.processMouseUp — morphic.js:11502
  Completes clicks or drops and clears press/drag state.
* HandMorph.prototype.processMouseMove — morphic.js:11563
  Updates the pointer position, hover transitions, drag threshold, and carried
  morph position.
* HandMorph.prototype.processTouchStart — morphic.js:11458
* HandMorph.prototype.processTouchMove — morphic.js:11481
* HandMorph.prototype.processTouchEnd — morphic.js:11495

Current Scala.js limitation:
SnapCodeEditor creates detached block morphs and calls fullImage(). It does not
retain a WorldMorph/HandMorph tree. Consequently none of the original hit testing,
pointer dispatch, keyboard focus, menus, or dragging described here is active in
the rasterized preview automatically.


2. Keyboard focus and text editing
----------------------------------
Snap uses a hidden HTML textarea as the browser input bridge, but keeps selection,
cursor, and edit ownership in Morphic objects.

* WorldMorph.prototype.initKeyboardHandler — morphic.js:12227
  Creates or reuses textarea#morphic_keyboard and installs keydown, keyup,
  keypress, and input listeners. Events are forwarded to world.keyboardFocus.
* WorldMorph.prototype.edit — morphic.js:12811
  Focuses the world canvas and hidden textarea, creates a CursorMorph, assigns
  keyboardFocus, and inserts the cursor beside the edited StringMorph.
* WorldMorph.prototype.stopEditing — shortly after WorldMorph.edit
  Commits reactToEdit, destroys the cursor, and clears keyboard focus.
* CursorMorph constructor — morphic.js:5663
* CursorMorph.prototype.processKeyDown — morphic.js:5717
  Handles Enter, Escape, Tab/back-tab, arrows, and editor shortcuts.
* CursorMorph.prototype.processKeyUp — morphic.js:5775
  Synchronizes selection and cursor position from the hidden textarea.
* CursorMorph.prototype.processInput — morphic.js:5797
  Copies changed textarea content into the target text morph and reruns layout.
* StringMorph.prototype.edit — morphic.js:8977
* StringMorph.prototype.mouseDownLeft — morphic.js:9029
* StringMorph.prototype.mouseClickLeft — morphic.js:9055

Editable parameter text is normally a StringMorph owned by an InputSlotMorph.
Clicking the slot ultimately invokes StringMorph.edit, which expects a containing
WorldMorph to own keyboard focus.

Important current behavior:
SnapCodeEditor passes line.label.replace("%", "%%") to setSpec. The doubled
percent signs are literal text, so Snap does not construct interactive %n, %s,
%b, command, reporter, or variadic parameter morphs for that preview. An
interactive editor needs a structured block specification or direct slot-child
construction instead of an escaped source-code label.

  Repositions top-level scripts into a regular arrangement.

* ScriptsMorph.prototype.cleanUpSpacing — blocks.js:8481

Complete insertion chain:

1. HandMorph.processMouseDown identifies a draggable morph.
2. Pointer movement crosses the drag threshold and HandMorph.grab runs.
3. The morph follows HandMorph during processMouseMove.
4. attachTargets/closestAttachTarget calculate compatible insertion points.
5. HandMorph.drop resolves an owner whose wantsDropOf accepts the morph.
6. Command snap reconnects stacks, or reporter snap calls replaceInput.
7. Parent fixLayout methods propagate changed positions and dimensions.
8. changed/fullChanged schedule the damaged region for the next world cycle.


6. Block specifications and child creation
------------------------------------------
Snap block specs are not merely labels. Percent tokens construct child input,
symbol, command-slot, reporter-slot, and variadic morphs.

* SyntaxElementMorph.prototype.labelParts — blocks.js:309
  Maps percent-token names to constructors and special label elements.
* SyntaxElementMorph.prototype.labelPart — blocks.js:1887
  Constructs a child morph for a parsed spec token.
* BlockMorph.prototype.parseSpec — blocks.js:3163
* BlockMorph.prototype.setSpec — blocks.js:3199
  Destroys old label parts, parses the specification, creates children, applies
  input options, fixes layouts/colors, and rerenders the block.

This spec-to-child stage must be represented explicitly in an SVG editor because
it determines not only text but also the interactive hit targets and nested
layout structure.

SnapShapeFactory reproduces outline geometry only. It does not measure labels,
wrap rows, size inputs, measure nested C-slot stacks, position attached command
stacks, or arrange top-level scripts. Exact SVG composition must port those
layout rules or consume the final bounds produced by retained Snap morphs.


8. Intended Scala.js/SVG migration boundary
-------------------------------------------
The long-term editor should preserve behavioral rules while replacing global
Morphic infrastructure:

* Keep/port low-level command, reporter, hat, and C-slot geometry.
* Keep the rules embodied by setSpec/labelPart, replaceInput, attachTargets,
  closestAttachTarget, snap, and the relevant fixLayout methods.
* Replace WorldMorph, HandMorph, damaged-region canvas redraw, and hidden-textarea
  focus ownership with Scala.js controllers and native SVG/DOM event targets.
* Represent every slot and nested block as retained structured data so it can be
  focused, hit-tested, dragged, inserted, and serialized without pixel probing.
* Use native SVG groups and paths for rendering, and browser focus/pointer events
  for interaction.
* Keep source method names and vendor line references both here and alongside the
  exact shape translations in SnapShapeFactory.
