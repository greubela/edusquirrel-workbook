# Turtle Editor Refactor Plan

## 1. Current Implementation Overview

The refactored turtle editor models block metadata through `TurtleBlockDefinition`, which exposes the block's evaluation type, SVG shape metrics, and a list of typed `TurtleBlockConnection`s that describe every drop zone (stack, enclosed body, or parameter).【F:src/main/scala/interactionPlugins/turtleEnvironment/TurtleBlock.scala†L8-L205】【F:src/main/scala/interactionPlugins/turtleEnvironment/TurtleBlock.scala†L237-L399】 Instances of these definitions live inside `TurtleBlock`, and structured programs are represented by `TurtleStructuredBlock`, which now stores children in a uniform `connectionChildren` map keyed by connection identifier.【F:src/main/scala/interactionPlugins/turtleEnvironment/TurtleStructuredBlock.scala†L3-L71】 Helpers transform that tree into executable commands by turning parameter connections into nested `TurtleExpression`s and flattening enclosed stacks recursively.【F:src/main/scala/interactionPlugins/turtleEnvironment/TurtleStructuredBlock.scala†L22-L70】

`TurtleBlockProgram` manages the mutable program tree. Paths are expressed through `IntoConnection` segments, letting the program insert, move, or detach blocks from any connection while sanitising payloads against the connection's accepted data types.【F:src/main/scala/interactionPlugins/turtleEnvironment/TurtleBlockProgram.scala†L6-L200】 The program also guards the root "when program started" block and keeps the stored tree normalised before notifying listeners via Laminar signals.【F:src/main/scala/interactionPlugins/turtleEnvironment/TurtleBlockProgram.scala†L21-L135】

`HtmlTurtleEditorArea` renders the entire program as a single SVG scene. A layout pass transforms the structured tree into `StackLayout`/`RenderedBlock` data, computing relative geometry for each connection and assembling drop targets with the accepted data types.【F:src/main/scala/interactionPlugins/turtleEnvironment/HtmlTurtleEditorArea.scala†L18-L233】 The SVG layer renders blocks with nested groups so enclosed stacks sit visually inside their parent shapes, parameter slots host reporter bubbles, and highlighted drop zones follow the geometry while pointer-driven drag operations resolve to the closest compatible `DropTarget`.【F:src/main/scala/interactionPlugins/turtleEnvironment/HtmlTurtleEditorArea.scala†L215-L452】 Pointer drags start on block groups, stream pointer moves through an event bus, and resolve drops by consulting the layout index—palette drags continue to rely on the shared `TurtleBlockDragContext` so both interaction modes converge on the same mutation API.【F:src/main/scala/interactionPlugins/turtleEnvironment/HtmlTurtleEditorArea.scala†L235-L452】

## 2. Target Architecture

* **Typed blocks & connections** – Blocks advertise their evaluation type and the connection schema they expose; each connection records accepted `TurtleDataType`s, geometric placement, and default children factories. This enables consistent tree manipulation and program sanitisation driven by metadata rather than UI heuristics.【F:src/main/scala/interactionPlugins/turtleEnvironment/TurtleBlock.scala†L8-L205】
* **Geometry-aware tree** – `TurtleStructuredBlock` stores all child relationships keyed by connection id, and the layout engine converts that tree into relative coordinates so nested stacks are enclosed visually while remaining structurally sound for execution.【F:src/main/scala/interactionPlugins/turtleEnvironment/TurtleStructuredBlock.scala†L22-L70】【F:src/main/scala/interactionPlugins/turtleEnvironment/HtmlTurtleEditorArea.scala†L96-L210】
* **Single-SVG rendering pipeline** – The editor renders blocks, enclosed bodies, and parameter slots within one SVG, using computed transforms instead of CSS stacking. Drop targets and pointer previews are layered atop the scene, providing spatial feedback during drag operations.【F:src/main/scala/interactionPlugins/turtleEnvironment/HtmlTurtleEditorArea.scala†L215-L452】
* **Pointer-centric drag mechanics** – Pointer drags capture the dragged block group, compute the closest compatible drop target via distance calculations on `TurtleRectangleArea`, and on release invoke the shared mutation API. Palette drags reuse the same resolution logic via HTML5 `dragover`/`drop` handlers, keeping user flows consistent.【F:src/main/scala/interactionPlugins/turtleEnvironment/HtmlTurtleEditorArea.scala†L235-L452】

These foundations let the editor maintain true nesting semantics, typed drop validation, and SVG-driven visuals while preserving the execution pipeline and program serialisation expected elsewhere in the turtle environment.
