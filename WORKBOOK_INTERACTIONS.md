# Workbook interaction roadmap

Use the [migration inventory](docs/digital-workbook-migration.md) for current
edition status, source references and remaining content gaps. This roadmap
summarizes directions for reusable interactions; it is not an API inventory or a
commitment to implement every idea.

## Reuse before adding editors

Text, choices, answer tables, sorting and ordering already cover many knowledge
checks and reflections. Small interactions should render inline. Add a dedicated
editor when the task needs a sustained workspace, such as mail triage, programming
or simulation. Follow the [interaction architecture](docs/workbook-interaction-architecture.md)
for shared models, state binding, grading and optional fullscreen placement.

## Remaining reusable capabilities

| Capability | Potential uses |
| --- | --- |
| Image annotation and hotspots | Phishing screenshots, hazard marking and source-diagram analysis |
| Inspectable network/training simulation | Autonomous systems and multilayer image-recognition activities |
| Scatter/cluster experiments | k-NN/k-means lessons with saved labels, distances and explicit unknown-class policies |
| Structured scene tables and CSV import/export | Visual-novel scenes, nested data and scene previews |
| Evidence and argument organization | Comparing sources, criteria and justified judgments |

Use local, inspectable teaching data where it meets the learning objective.
Real wallets, live mail transport and downloaded recognition models are not
prerequisites for the corresponding conceptual exercises.

## Edition priorities

Phishing already has a local mailbox and writing practice. Remaining work centers
on source explanations, screenshots, attempt comparisons and deeper technical or
social modules. Domain inspection should expose evidence rather than promise an
automatic safety verdict.

Blockchain already has ledger, hashing and bounded mining experiments. Review
supplementary hints and pedagogical equivalence before adding speculative wallet
or transaction services.

Evacuation should reuse the existing EVA2 engine. Prioritize source-layout review,
comparable saved experiments and explicit model assumptions over another simulator.

## Acceptance

Save answers through interaction history and the existing synchronization layer.
Keep domain calculations cross-platform, presentation in CSS, and editor resources
owned by their mounts. Verify meaningful behavior, restored answers and accessible
browser flows; review teaching content with its intended audience. Automated
feedback is appropriate only when the task has a defensible grading contract.
